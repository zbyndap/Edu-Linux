Instalace Debianu a rozdělení disku

Než začnete instalovat, ověřte si na těchto otázkách a zdrojích, jak instalace Debianu probíhá a proč se disk dělí na víc oddílů podle standardu FHS.

Badatelské otázky

    Doporučené rozdělení diskových oddílů podle účelu serveru

    Rozdělení disku (na tzv. připojovací body, mount points) se po instalaci těžko mění, proto se volí podle toho, k čemu bude počítač sloužit. Projděte si pět typických scénářů — s tím posledním, „Server“, budete dnes reálně pracovat.

    1. Domácí a kancelářský počítač

    Nejjednodušší varianta pro běžného uživatele bez zvláštních nároků:

    Připojovací bodVelikostSouborový systémÚčel
    /30–50 GBext4Kořenový systém
    /homezbytek diskuext4Data uživatelů
    swap2–8 GBswapOdkládací prostor

    Výhoda: při přeinstalování systému zůstanou data v /home nedotčená, pokud se pouze zformátuje /.

    2. Školní nebo kancelářská pracovní stanice (UEFI)

    Připojovací bodVelikostSouborový systémPoznámka
    /boot/efi512 MBFAT32UEFI zavaděč — jen na UEFI systémech
    /boot1 GBext4Jádro a GRUB
    /40 GBext4Systém a aplikace
    /home50–100 GBext4Domovské adresáře
    swapdle RAM, max. 8 GBswapVirtuální paměť

    Oddělený /boot usnadňuje správu zavaděče GRUB nezávisle na zbytku systému.

    3. Server (webový, databázový)

    Připojovací bodDoporučená velikostÚčel
    /boot1 GBJádro a zavaděč
    /20–30 GBSystém
    /var20–100 GBLogy, cache, databáze, webový obsah
    /home5–10 GBDomovské adresáře správců
    swap4–16 GBVirtuální paměť

    Proč oddělit /var: obsahuje logy, cache a databáze, tedy data, která rychle rostou a mění se za provozu. Když se /var zaplní, zbytek systému zůstane funkční.

    4. Datový nebo souborový server

    Připojovací bodVelikostÚčel
    /30 GBSystém
    /srvvětšina diskuSdílené soubory, FTP, web
    swapdle RAMVirtuální paměť

    /srv slouží k ukládání dat, která server poskytuje ven — sdílené soubory (Samba/NFS), FTP, webový obsah.

    5. Virtualizační server (Proxmox, KVM)

    Připojovací bodVelikostÚčel
    /boot1 GBJádro a zavaděč
    /50 GBSystém
    /var/lib/libvirtvětšina prostoruDisky virtuálních strojů
    swap8–16 GBVirtuální paměť

    Virtuální stroje zabírají velký a rychle rostoucí prostor — samostatný oddíl zabrání, aby zaplnily celý disk.

    Přehled nejčastějších připojovacích bodů (FHS)

    BodPoužití
    /Kořen systému — základní adresáře a binární soubory
    /bootJádro Linuxu a zavaděč GRUB — kritické pro start systému
    /boot/efiUEFI zavaděč — jen na systémech s UEFI
    /homeDomovské adresáře uživatelů — osobní data
    /varLogy, databáze, cache — data měnící se za provozu
    /srvData poskytovaná službami — web, FTP, sdílené soubory
    /tmpDočasné soubory aplikací — obvykle se maže po restartu
    /optDoplňkový software instalovaný mimo balíčkovací systém
    /usrProgramy a knihovny — sdílená, jen ke čtení určená část systému
    swapVirtuální paměť — diskový prostor pro přetečení RAM

    Didaktická poznámka pro studenty: Zapamatujte si jedno jednoduché pravidlo — čím víc služeb server poskytuje a čím víc dat se za provozu mění, tím víc se oddíly oddělují:

    • Pracovní stanice → /, /home, swap
    • UEFI počítač → navíc /boot/efi
    • Server → navíc oddělit /var
    • Datový server → navíc oddělit /srv
    • Virtualizační server → navíc oddělit prostor pro virtuální stroje

    Hlavní důvod: když se jeden oddíl zaplní (typicky /var zaplněný logy), zbytek systému zůstane funkční a přístupný přes SSH — nezhroutí se vám celý server.

    Za horizontem dnešní kapitoly

    LVM (Logical Volume Manager)umožňuje oddíly za provozu zvětšovat, aniž byste museli disk přepartitovat od nuly.
    RAIDzrcadlení nebo rozložení dat na víc disků kvůli odolnosti proti výpadku disku.
    Šifrování disku (LUKS)ochrana dat, pokud se fyzický disk nebo server dostane do nepovolaných rukou.
    Automatizovaná instalaceKickstart/preseed nebo Ansible dovolí nainstalovat desítky serverů stejně a bez klikání.

    Hodnocení a sebehodnocení

    Hodnoticí rámec platí pro celý předmět Serverové služby (4 kritéria); u dnešní kapitoly se promítá takto.

    Teoretické znalosti

    25 %
    • Začínající — nerozumí, proč se disk dělí na víc oddílů.
    • Rozvíjející se — zná pár mount pointů, ale neumí zdůvodnit volbu pro konkrétní typ serveru.
    • Očekávaná úroveň — jasně rozumí FHS a umí vybrat vhodné rozdělení disku podle účelu počítače.
    • Nad rámec — diskutuje i pokročilá témata: LVM, RAID, šifrování disku.

    Praktická realizace

    40 %
    • Začínající — instalace selhala nebo je nekompletní.
    • Rozvíjející se — server funguje, ale s chybami (síť, oddíly, uživatel).
    • Očekávaná úroveň — server správně nainstalován přesně podle zadání, přípojné body vypsané a doložené screenshotem, Guest Additions funkční, klient naklonován a síťové karty správně nastaveny.
    • Nad rámec — navíc zdokumentováno a připraveno k rozšíření o další služby.

    Aplikace v praxi

    20 %
    • Začínající — neví, jak bude server dál rozšiřovat.
    • Rozvíjející se — vidí spojitost s dalšími kapitolami jen obecně.
    • Očekávaná úroveň — umí říct, co konkrétně přibude v 1.3 (síť), 1.5 (DNS) apod.
    • Nad rámec — kriticky zhodnotí, jestli zvolené rozdělení disku vydrží i po přidání služeb.

    Samostatnost a zapojení

    15 %
    • Začínající — závislý na pomoci u každého kroku.
    • Rozvíjející se — poradí si se základní instalací, u chyb potřebuje pomoc.
    • Očekávaná úroveň — pracuje samostatně, chyby si dohledá v dokumentaci.
    • Nad rámec — experimentuje (jiné rozdělení, jiné parametry VM), pomáhá spolužákům.
